# AI OnCall 平台开发计划

## 1. 文档目的

本文档用于将现有需求文档、模块拆分文档和系统架构文档转化为可执行的项目实施计划，明确项目从 0 到 1 的推进步骤、每一步的建设目标、主要任务、产出物、依赖关系和完成标准。

本文档关注“按什么顺序做、每一步做成什么样”，作为后续开发、协作和迭代的执行路线图。

## 2. 计划原则

开发计划遵循以下原则：

1. 先定基础，再做业务，再做增强能力。
2. 先完成主链路，再扩展辅助功能。
3. 前后端并行推进，但以前端空页面和后端空接口为起点逐步闭环。
4. 优先形成可演示、可调试、可扩展的工程骨架。
5. 每一步都有明确产出，不做无法验收的“半完成状态”。

## 3. 总体实施顺序

建议按以下顺序推进：

1. 设计基线冻结
2. 项目初始化
3. 后端基础能力建设
4. 前端基础能力建设
5. 认证与权限模块
6. 会话与消息模块
7. 知识库管理模块
8. RAG 检索能力
9. 告警中心模块
10. 工具中心模块
11. AI 编排与告警分析能力
12. 审计与运营能力
13. 集成联调与测试
14. 部署与演示环境
15. 项目收尾与展示优化

## 4. 分阶段开发计划

## 阶段 0：设计基线冻结

### 目标

统一系统范围、模块划分、架构方向和技术栈，避免边做边推翻。

### 需要完成的内容

- 确认需求文档内容
- 确认业务模块划分
- 确认系统架构分层
- 确认前端技术栈为 Vue 3
- 确认后端技术栈为 Go + Gin + GORM
- 确认 Python AI 服务技术栈为 FastAPI + LangChain + LangGraph
- 确认 AI 编排框架采用 Eino
- 确认基础设施选型为 MySQL、Redis、Kafka、Elasticsearch、Milvus
- 确认 Go 与 Python AI 服务之间通过 gRPC 通信

### 产出物

- 需求文档
- 模块拆分文档
- 系统架构文档
- 开发计划文档

### 完成标准

- 所有人对系统目标、边界和总体方案无重大分歧
- 后续可以直接进入建仓和开发

## 阶段 1：项目初始化

### 目标

建立统一仓库结构、开发规范和运行方式，让项目具备可开发、可运行、可提交的基本形态。

### 需要完成的内容

- 初始化前端项目
- 初始化 Go 后端项目
- 初始化 Python AI 服务项目
- 设计 monorepo 目录结构
- 初始化 AI 模块目录和 Eino 编排目录
- 初始化 LangChain/LangGraph 目录结构
- 建立配置文件规范
- 建立环境变量规范
- 建立本地开发启动方式
- 建立 Docker Compose 基础依赖
- 建立 README 和启动说明
- 建立 Git 提交和分支规范

### 产出物

- 前端目录结构
- Go 后端目录结构
- Python AI 服务目录结构
- `.env.example`
- `docker-compose.yml`
- 项目启动说明

### 完成标准

- 新人拉取仓库后可本地启动前端、Go 后端、Python AI 服务和基础依赖
- 前后端服务均有健康检查或默认首页

### 需要完成的内容

- 建立中间件体系
- 建立日志组件
- 建立配置加载能力
- 建立数据库连接与迁移机制
- 建立 Redis 连接
- 建立基础模型层和 repository 规范
- 建立请求日志和链路追踪基础接入
- 建立 AI 抽象接口和 Eino 编排基础骨架
- 建立 Go 到 Python AI 服务的调用客户端

### 产出物

- 后端启动入口
- 路由注册机制
- 中间件基座
- 数据库基座
- 缓存基座
- 日志与错误处理基座

### 完成标准

- 后端具备统一工程骨架

## 5. 关键依赖关系

各阶段存在以下关键依赖：

1. 项目初始化必须先于所有编码工作。
2. 后端和前端基础能力必须先于业务模块开发。
3. 认证与权限先于大多数业务页面和受保护接口。
4. 会话模块先于智能对话闭环。
5. 知识库管理先于 RAG 检索。
6. 工具中心先于工具增强问答。
7. 告警中心先于告警分析。
8. 审计与运营应在核心主链路稳定后接入，但日志埋点基础应尽早完成。
9. Eino 编排骨架应先于复杂 AI 场景流程落地。
10. Python AI 服务骨架应先于 LangChain/LangGraph 工作流落地。

## 6. 核心里程碑

建议设置以下里程碑：

### 里程碑 1：工程骨架完成

表示前后端项目已初始化，可本地启动，可登录基础页面。

### 里程碑 2：对话主链路完成

表示用户可登录、创建会话、发送消息并看到流式回复。

### 里程碑 3：知识问答主链路完成

表示用户可上传知识并在对话中获得带引用的知识增强回答。

### 里程碑 4：告警分析主链路完成

表示外部告警可接入，前端可查看告警详情和 AI 分析。

### 里程碑 5：平台闭环完成

表示对话、知识、告警、工具、审计五大核心能力形成完整闭环。

## 7. 每阶段的交付检查方式

每个阶段完成后，建议至少检查以下内容：

- 代码是否可运行
- 页面是否可访问
- 接口是否可调用
- 日志是否可追踪
- 基础异常是否可处理
- 文档是否同步更新

## 8. 建议的执行方式

为了保证推进效率，建议每一步都遵循同一执行模式：

1. 先补充该阶段对应的设计文档。
2. 再初始化代码骨架。
3. 再打通最小闭环。
4. 再补异常处理和日志。
5. 最后补测试和文档。

## 9. 当前结论

当前项目最合理的推进方式，不是一次性同时做完所有功能，而是按“骨架 -> 主链路 -> 增强能力 -> 观测与演示”的顺序推进。

如果严格按本计划执行，项目会始终保持三个特点：

- 每一阶段都有成果
- 每一步都有验收标准
- 系统复杂度随着业务闭环逐步增长，而不是一开始失控
